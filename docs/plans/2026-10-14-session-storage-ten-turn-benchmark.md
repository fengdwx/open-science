# Open Science：10 轮对话保存与读取对照

2026-10-14。这里的 **10 轮是每个会话累计 10 次用户提问**。原版 JSON 基线为 `488b8f520935278958335399ca92c83d9f8eda54`；当前旧 JSON、新 JSONL 使用同一份候选源码。每种存储路径独立重复测量 6 次，顺序 ABC / BCA / CAB 循环两遍。延长到 10 轮时只修改测试负载、基准和报告，没有修改生产存储代码。本文从原始综合记录独立整理，只引用这一轮结果。

表中性能数据来自本轮正确性修复之前的 10 轮冻结版本；本轮提交版本的正确性检查另行记录，尚未重跑这套性能基准。

历史基准使用单帧、单分支样本进行线性追问，未覆盖多分支、多 Frame 会话的完整读取回退。当前实现为保留修订导航，对这类复杂会话返回完整会话；下表的分页收益不能推广到该路径。

**本次新增追问的累计保存耗时，新 JSONL 比原版 JSON 低 29.46%～34.48%，会话文件累计写入量低 96.68%～97.48%。同一种负载随着历史增长，省下的绝对时间和字节量增加；耗时节省比例并不保证随轮数提高。第 10 轮的 JSONL 完整加载仍为原版的 1.99～2.41 倍。**

三个官方文件原本分别有 2、2、3 次用户提问，先各增加一条 32 KiB 控制追问后为 3、3、4 轮。本次完整保留这些内容，再分别补 7、7、6 轮。新增轮次按原始真实用户轮型循环，匹配智能体回复段数、正文 UTF-8 字节数、工具调用数以及输入/结果的 JSON 结构和编码字节预算。正文和工具数据为明确标注的模拟占位内容，没有实际调用模型、执行工具或产生新的研究结果。原始流式时序不可还原，采用每 500 ms 一批、每批最多 4 个文本事件、正文约 192 字节的模拟输入，工具启动和结果各一批，按原约 2 秒策略合并保存，最后不足 2 秒的尾批单独提交。

新增工具事件经过实际 ACP mapper、sanitizer、RuntimeOwner 和存储路径，报告记录原模板、模拟输入、实际保留三组字节数。工具密集不等于每条结果都很大：降雨的 121 工具模板中，只有 11 条带正文结果；没有人为扩成 MB 级工具结果来放大收益。

## 测量口径与业务含义

- **保存**：经过实际 RuntimeOwner、StateOwner、Repository、SQLite 与会话文件同步。投资和分子统计第 4～10 轮，降雨统计第 5～10 轮，每次重复三个场景合计 326 次提交。先在每次重复内累加该场景全部保存耗时，再取 6 次中位数。排除原始历史、前置控制轮及独立标题修改；不包含模型或工具执行、IPC、界面、文件索引、provenance 观察器及约 2 秒调度等待。这不是整段回复的墙钟时长。
- **最近展示与全部展示**：JSONL 查询已有 SQLite 展示索引，每页 80 条消息/工具业务记录，加上关联问题上下文；全部展示页覆盖当前活动分支。旧 JSON 的统一 API 直接返回完整会话。原版 JSON 只读取一次，再由基准在内存切出展示页，不重复读取完整 JSON 来抬高基线；不能据此断言原应用界面实际执行了相同切页操作。三条路径的返回结构和数据量不同。
- **完整加载**：在新进程内计时构造 `SessionRepository`，调用 `loadSessionWithDiagnostics`，参数为 `preserveRuntimeState: true`、`mode: 'read-only'`。包含完整文件读取、JSONL 追加记录应用、会话解码和路径还原，返回完整会话图、消息、工具、运行状态及产物引用。它不是崩溃修复或整个应用启动，也不读取产物附件本体。继续追问、分叉、导出等业务中的完整加载步骤会承担这类成本；本次未测量整个业务流程的延迟或完整加载次数。
- 展示读取计时前已连接 SQLite、完成迁移并构造 Repository；完整加载计时包含 Repository 构造，不使用分页数据库连接。两种计时不能相加，也不能相互替代。进程启动、源码编译、初始输入读取与计时后的 canonical/SQL 核验均不计入。
- 运行环境为 Apple M5 Pro、Node v24.13.0、Darwin 27.0.0。使用新进程但未清空 OS 文件缓存；不是冷盘、UI 绘制或模型端到端测量。当前任务没有并行运行其他负载测试，但仍属于共享开发机实验。
- 三种格式从同一完整文档及业务 SQL 开始。JSONL 测试副本的首行快照在计时前构造，修订号及业务字段相同；这是等价夹具初始化，不是产品自动迁移，也不测创建或导入 `.science` 的完整耗时。展示索引首次建立的成本记在最前面的控制轮保存中；下表只统计其后新增追问。
- 保存期间保留原约 2 秒合并策略。旧 JSON 使用原读写路径，不自动迁移、不建立展示索引；新会话使用 JSONL 业务记录追加及分页。字节量只统计会话文件，SQLite/WAL 不在字节统计内，但 SQLite 处理时间在保存耗时内。

## 核验与复现

- 共 18 组正式运行、54 个案例，8,676 次计时保存；新进程完整读取 162 次，展示/旧记录读取 API 270 次；另有 9 个不计时预检案例。
- 每轮均检查先前消息、工具和产物完整保留，新增正文、工具状态/结果、用量、运行记录符合预期；逐轮完整 canonical 文档和业务 SQL 在三条路径、所有重复间一致。页面逐字段与完整内容核对；旧 JSON 无迁移、无历史索引。
- 负载 helper 单测 3/3 通过；基准 Node/sandbox 类型检查、ESLint 和格式检查通过。生产代码未改，本次未重复注入崩溃故障；本轮验证了旧格式保留和完整内容一致性，但不把性能测试称为新的故障恢复验收。提交前的检查范围与实际结果另见[本地提交前检查](2026-10-14-session-storage-precommit-check.md)。
- 完整读取与展示 API 的计时边界见“测量口径与业务含义”；使用相同本机环境。读取每格仅 6 个样本，p95 为最大值，不推断长期尾延迟。
- 三个官方包、528 个种子文件、prepare.json 测前测后不变；正式测量时的工作树与冻结候选的 5,237 个源码文件、3,731 个额外依赖源码/配置文件一致。独立核验文件保存逐项数值和实体文件检查结果。
- 756 个基础统计值独立复算无差异，另核对全部逐轮/累计/控制统计；18 份写入、162 份完整读取、270 份页面操作及 54 份控制输入报告均与总结果一致。核验 126 个最终/预检会话文件和 54 个控制会话文件的格式、修订号；360 个模拟追问轮的工具输入/输出字节全部保留，未通过丢弃结果减少负载。

## 复核入口
