2026-10-14。检查对象为隔离工作树 `session-storage-plan/open science`，分支 `fix/session-storage-incremental`，基线提交 `488b8f520935278958335399ca92c83d9f8eda54`。未修改原工作目录中的其他分支。

**最终相关回归、静态检查、构建及 7 项 Electron/Web 实际界面测试通过。** 性能结果沿用之前冻结版本的 10 轮测量，没有将本轮正确性验证称为性能复测。

## 实现范围

- 新会话使用 JSONL 业务记录追加，保留原约 2 秒合并保存和未完成正文的保存取舍。
- 旧 JSON 保留原读写路径，不自动迁移，不建立分页索引。
- 普通线性 JSONL 会话按需读取展示页；多分支或多 Frame 会话保留完整读取，以维持修订导航；需要完整运行状态的操作仍加载完整会话。
- 保留已有异常恢复及版本冲突规则，不引入压缩、字段补丁、整会话校验和或新的后台整理任务。

## 本轮检查发现并修复的问题

1. **磁盘使用诊断漏算新 JSONL 主文件。** 修正文件分类，兼容旧 sidecar 和 legacy JSON backup，避免诊断低报会话文件数量与大小。此诊断工具不参与已归档性能表的计时或累计写入统计。
2. **较旧的首页响应可能使界面停留在加载状态。** 当请求仍对应当前待加载会话但响应修订号已经过期时，使用已有的过期游标错误和重试界面；已取得完整会话后，迟到的页响应仍被忽略。
3. **同修订号的外部文件替换可能留下旧展示索引。** 增量更新复用已有文件指纹，并核对索引是否来自本次保存之前的权威文件；不匹配时走已有完整重建。正常增量路径只多比较一个短字符串，没有新增全会话遍历或文件扫描。
4. **首次完整更新可能混合不同分支、清空正在编辑的草稿。** 页响应仅携带现有分支 ID；完整数据到达时保留当前窗口的分支及 Frame，沿原逻辑生成消息和工具列表。分支消失或不可见时采用有效的远端选择；分页与完整视图保持同一展示作用域。
5. **复杂会话分页冷打开后缺少修订导航。** 复用现有完整读取回退，索引只在明确为线性会话时允许分页。旧索引没有这一标志时先完整解码，确认线性才更新索引并分页；复杂图直接完整返回，不进入重复建索引循环。没有增加数据库表或新的修订导航协议。

## 实际界面与恢复验证

最终七项全部通过，耗时约 1.2 分钟，覆盖以下业务行为：

1. 延迟的 Web 改名回执不会恢复已删除会话。
2. 另一客户端切换分支时保留编辑草稿及独立输入框草稿；发送、重开后的版本导航正确。
3. 修订冲突重试保留尚未发送的草稿，不多追加一次提问。
4. 旧 JSON 与新 JSONL 共存，旧记录续问及冷打开不触发迁移或建索引。
5. 线性 JSONL 首屏分页、加载更早记录、取得完整会话后续问；120 条工具记录及历史消息完整保留。
6. 多分支 JSONL 首次冷打开即保留修订导航；续问及再次冷打开后，隐藏分支、消息、工具结果和完整会话图均保留。
7. 强制终止进程后恢复已提交会话，继续提问只追加一次。

检查过程中，前两次运行分别暴露草稿丢失和冷打开修订导航缺失，均先补回归再修复。采用复杂会话完整读取后，第三次运行显示原分页夹具含有隐藏分支，其“只加载首页”的期望不再适用。因此将新分页用例拆成线性分页和复杂会话完整回退两项，保留各自的调用时机与内容完整性断言，并增加再次冷打开后的完整图核对；原有跨客户端用例的断言保持不变。最终运行七项全部通过。

## 性能证据的适用范围

[10 轮性能报告](2026-10-14-session-storage-ten-turn-benchmark.md)和[领导说明](2026-10-14-session-storage-ten-turn-leadership-summary.md)保留原始数据，提升及退步均未改写。这些数据来自本轮正确性修复之前的冻结候选，不能标为修复后提交版本的新实测结果。

三个场景各自六次重复的中位数相加：新增追问的保存耗时 13.56 秒 → 9.09 秒，会话文件累计写入 320.41 MB → 8.73 MB。展示读取有改善，完整历史加载 71.32 ms → 158.09 ms，仍然变慢。保存合计是分散在 326 次后台保存中的累计处理成本；读取数据不包含界面渲染或用户操作全过程。

归档的三份原始样本清单均为一帧一分支，基准代码沿同一分支追加追问和运行段，未执行消息修订或分支切换。由此将历史负载界定为线性追问；本轮未覆盖复杂会话完整读取回退的性能。历史临时最终副本已清理，归档只保存最终内容摘要而非帧/分支计数，因此没有把这次代码与清单复核说成重新打开最终文件的实体检查。
